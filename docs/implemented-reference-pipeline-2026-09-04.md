Реализация улучшений OMNI REELS ANTON, 4 сентября 2026 года.

Изменения внесены в локальную рабочую копию после [аудита](audit-reference-pipeline-2026-09-04.md). Платные изображения, видео и анализ готового видео при разработке не запускались. Продакшен и его очереди не изменялись.

Рабочая последовательность: выбранный референс → сценарий и речевые интервалы → единый сохранённый адаптированный план → раскадровка и существующая проверка → видеопромпт из того же плана → генерация и сборка.

Что изменилось:

| Область | Результат |
| --- | --- |
| Референс | Явно выбранный источник не заменяется другим при ошибке. Для подготовки нужен полный визуальный таймлайн. |
| Формат | Говорящий аватар, тематические перебивки и отдельные товарные B-roll. Исходные действия человека с товаром заменяются предметной вставкой. |
| Товар | Без людей и рук, на устойчивой опоре. Внутри плана сохраняются форма, масштаб и положение; меняются камера или фокус. Отдельная склейка возвращает аватара без товара. |
| Визуал | Сеттинг, свет, одежда и композиция берутся из адаптированного плана. PiP сохраняет наблюдаемое положение аватара; в товарных вставках слой аватара отсутствует. |
| Промпты | Каждый интервал получает действие, камеру, окружение и предметы. Точная реплика приведена один раз. Повторяющиеся инструкции сокращены без обрезания описания первого или изменившегося кадра. |
| Подготовка | План сохраняется с подписью входных данных. Просмотр читает готовый план; отдельная кнопка запускает подготовку. Повторное создание ролика использует подходящий сохранённый план. |
| Запуск | Ручной и автоматический запуск используют Omni-очередь. Провайдер сохраняется, аватар при отправке берётся из снимка ролика. |
| Бюджет ошибок | Окончательная ошибка задания или исчерпание попыток после истечения lease останавливают новую автогенерацию проекта. Уже созданные задачи продолжаются; ручной запуск доступен в пределах квоты. |
| Очистка | Удалены 22 неиспользуемых исходника, README заготовки и девять прямых зависимостей. Lock-файл потерял 97 записей пакетов без обновления версий оставшихся пакетов. |

Речь: ориентир — четыре слова на две секунды. Планировщик учитывает недозаполнение; локальная диагностика показывает длинные слова, приблизительную слоговую нагрузку, пунктуацию и неоднозначное произношение. На этапе сценария выбираются простые разговорные формулировки. После утверждения слова и их порядок сохраняются. Смена панели или B-roll не требует паузы; дополнительные слова и междометия не разрешены.

Слоговая оценка не предсказывает точное время произношения. Новая скорость не проверялась платными генерациями, поэтому исчезновение пауз и зажёвывания слов не заявляется как измеренный результат. Сохранённые длительности 20/30/40 секунд покрыты регрессиями.

В существующем визуальном QA раскадровки явные нарушения опоры, масштаба, пересечения твёрдых объектов и присутствия человека в товарной вставке стали блокирующими. Неопределённость и скрытая опора не расходуют повторную генерацию. По статичным панелям нельзя подтвердить динамику или синхронизацию губ; проверка готового видео не добавлена.

Текстовая подготовка по явному запросу по-прежнему использует существующие LLM-проверки и ограниченные исправления. Открытие вкладки промптов их больше не запускает. Генерация изображений раскадровки остаётся частью создания ролика.

Таймкоды описывают реальные интервалы плана. Google допускает интервалы и обычный язык, без обязательного описания каждой секунды. Это подтверждено при аудите по [официальной документации Google](https://ai.google.dev/gemini-api/docs/omni#timing-events); качество соблюдения интервалов через KIE отдельно не измерялось.

Ключевые модули: [общая подготовка](../ui/src/lib/server/omni/omni-prompt-preparation.ts), [адаптация под аватара](../ui/src/lib/server/omni/omni-avatar-reel-plan.ts), [временной план](../ui/src/lib/server/omni/storyboard/omni-storyboard-timeline.ts), [речевая нагрузка](../ui/src/lib/omni/storyboard/omni-speech-load.ts), [физические правила QA](../ui/src/lib/server/omni/storyboard-qa-contract.ts).

Для будущего развёртывания добавлены две идемпотентные миграции: `omni_generated_scripts.prepared_prompt_plan` и `omni_projects.automation_provider`. Старый Python scheduler перестаёт создавать новые задания; существующие legacy worker/poller оставлены для уже созданной очереди. Автоматический режим настраивается в Omni-проекте. Связи с клиентом для длительности, субтитров и Яндекс.Диска сохранены; автосохранение настроек привязано к явному ID клиента.

Проверки подготовки работают на локальных данных с подменёнными ответами API и базы: обычный аватар, взаимодействие с товаром в источнике, адаптация B-roll и PiP, точная речь, продуктовые маски, статическая физика, кэш, параллельная подготовка и сохранённый провайдер/аватар. Это проверки кода и контрактов, а не визуальная оценка новых роликов.

Результат проверки: финальная production-сборка с TypeScript и перечисленные регрессии прошли. Дополнительно прошли проверки семантического исправления, границ речи, товарного B-roll, контрактов раскадровки, её кэша и визуального QA, выбора референса, исходных интервалов и лимитов очереди. Целевой ESLint: ноль ошибок, десять оставшихся предупреждений о неиспользуемых состояниях и обработчике в старом `page.tsx`. Полный интерактивный проход UI и миграции на реальной базе не выполнялись.
